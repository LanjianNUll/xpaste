### 🔗 多设备同步：几台机器共用一份剪贴板历史

在一台设备上复制，另一台马上就能粘——而且上传的是**密文**，服务端解不开。

设置里新增「同步」页：打开开关会自动生成一串同步码，把它抄到另一台设备的输入框里点「加入」，
两边就开始共享同一份历史。不需要注册账号、不需要登录，同步码本身就是账号和密钥。

**同步码怎么变成账号和密钥**

```
同步码  XP1-XXXX-XXXX-…        ← 32 字节主密钥的 base32，只在你的设备上
   ├─ room_id = HKDF(master, "xpaste-room-v1")     中继路由用，公开
   ├─ key     = HKDF(master, "xpaste-content-v1")  AES-256-GCM 内容密钥，永不上传
   └─ proof   = HKDF(master, "xpaste-auth-v1")     鉴权凭证，中继只存它的 SHA-256
```

中继服务器看到的只有 `room_id`、密文、IV 和时间戳。它既解不开内容，也算不出 `proof`，
所以也没法冒充你的设备往里写东西。

**几个刻意的取舍**

- **图片暂不同步**：图片在库里是 RGBA 原始字节，一条动辄几 MB，塞进密文中继又慢又贵。文字、链接、颜色、文件路径照常同步
- **首次只回推最近 7 天**：避免把几年的历史一次性灌进中继，把新设备淹掉
- **合并靠内容指纹**：对端推来的记录用 `content_hash` 撞唯一索引，同一条内容在两台设备上只会存在一份，不会因为互相同步就翻倍
- **复制次数不跟着涨**：对端记录在本机第一次出现时计数就是 1，不把「同步过来」当成「又复制了一次」
- **换个同步码等于换身份**：游标和推送水位一起归零，不会把旧房间的进度套到新房间上

**同步节奏**：启用后每 5 秒对齐一次，也可以在设置里手动「立即同步」。同步来的新内容会广播
`clipboard://updated`，主窗口和快捷面板同时刷新。
